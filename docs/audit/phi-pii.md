## Containment check gaps (`scripts/e2e-verify/check-phi-containment.ts`)
The script already scans l2-data (incl. checkpoints), `/interactive/state`, `/events`, `/viz/*`, the proxies, employer/HR endpoints, the network log, marketplace JSON and hr-tool `audit.log`, and runs an I6 wallet↔employee linkage pass. It does **not** yet cover:
1. **Decrypt the HR `correlation.table.enc` with the workspace passphrase** and scan its plaintext for employee name/DOB/email + the 8-digit `tokenPIN` (I5). `.enc` files are skipped entirely (`walk` filter `:207`), so the largest employee-PII store on the insurer host is invisible; only member devices are decrypted.
2. **Add an I5 verdict**: assert the HR Tool is NOT co-located with the insurer, and that only `employeeIdHash/familyIdHash/tokenPinHash` cross the HR→employer wire (never names/DOB/PIN/employeeId).
3. **Needle the enrollment code (`tokenId`) and the plaintext 8-digit `tokenPIN`**, and flag any store/endpoint returning both together (`/api/export/tokens`, `correlation.table.enc`).
4. **Decode message payloads (base64/hex) before matching** and classify each as ciphertext vs base64-plaintext vs hex-plaintext — a base64-wrapped body evades the plaintext needle today.
5. **Treat clinical claim data as a containment target** (NDC, brandName, dateOfService, pay cents keyed by wallet) across checkpoints + claim RPCs + `/interactive/state` prescriptions/fulfillments — currently not needled, so cleartext claim history is unseen.
6. **Stop hardcoding `employeeId = cardholderId` (`:161`)**: pull the real `employeeId` from the HR table, and scan the sequencer's `enrolledMembers.employeeId` and `demoData.members` linkage, so I6 catches the seed/full-cycle path where wallet and employeeId differ.
7. **Scan `.pdf` and other skipped files** (`employer-documents/*.pdf` CP575 with EIN/company) for I5-adjacent PII; currently `.pdf`/`.enc` are filtered out.
8. **Probe the explorer and node proxies with the full `WALLET_READERS` set** (the explorer path uses only `l2_getClaimsByMember` `:242`), and assert the `/interactive/*` engine routes (esp. `register-member`) reject unauthenticated preimage-bearing POSTs.
9. **Capture member browser `localStorage`** (headless, known keys `zkt_walletId`/`zkt_enrollmentKey`) to catch the real enrollment key after a Restore (I3) — only the device `.enc` is checked now.
